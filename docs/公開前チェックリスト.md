## 履歴に機密が混入していた場合

現在のツリーから消すだけでは不十分。次のいずれかを取る。

| 状況 | 対応 |
|---|---|
| コミット数が少ない・公開前 | `git filter-repo` で該当ファイル/文字列を履歴から削除し、force push |
| 手に負えない | **リポジトリを作り直す**（`git init` からスカッシュした1コミットで再出発）。設計段階の今なら損失は小さい |

いずれの場合も、**漏れた資格情報は必ずローテーションする**（消せば安全、ではない）。

## 公開後に効いてくる設計上の配慮

| 項目 | 現状 | 公開時に必要なこと |
|---|---|---|
| 認証 | なし（`127.0.0.1` バインド + Tailscale で担保） | 他人が自分のサーバーに立てる前提なので、**READMEに「認証がないのでインターネットに直接晒すな」と明記**する。Basic認証の追加も検討 |
| UI言語 | 日本語のみ | 英語UIまたは英語READMEの充実。最低限、READMEの冒頭は英語にしてある |
| 外部ソースカタログ | 公開テストストリームのみ | 各URLのライセンス根拠をコメントで残す |
| FFmpegパス | `config.toml` の設定値 | 環境差が大きいので、起動時の能力検出結果を分かりやすく表示する |
